# 任务经验怎么记

用户选定要沉淀的问题后，在这里新建一页。标题用下次接手的人会搜索的症状或任务名。以后遇到同一问题，先核对适用条件，再把新的验证结果补回原页。

```markdown
# <任务或症状>

查找线索：<报错原文、常用叫法或同义词>
适用条件：<环境、版本、操作前提>

## 下次从这里开始

<先做哪项低成本检查？看到什么结果，才适合沿用以下做法？>
<已验证的有效步骤，以及怎样确认任务已经完成。>

## 已排除的路径

<试过什么，在什么条件下失败，证据是什么，只记录实际试过的路径。>

## 判断如何变化

- <日期>：<当时选了什么、理由和依据，仍待核实的猜测单独注明。>

## 依据

- [名称](相对该条目路径) <!-- sha256:64位小写摘要 -->
```

如果只有文档核对或提交记录，写明「已核对文档」或「已核对配置」。实际运行过的步骤再注明环境和结果。保留仍影响判断的未知项，其余空段可以删掉。
